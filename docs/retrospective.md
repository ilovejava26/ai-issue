## Sprint 1 — 기반 구축 (2026-11-09 ~ 11-13)

### Situation

저장소에는 README와 계획 문서만 있었고, 패키지 구조·테스트·CI가 전혀 없는 상태였다.
2주 안에 분석 기능까지 가려면 첫 주에 **재현 가능한 개발 환경과 품질 게이트**를 먼저 만들어야 했다.

### Task

- 이슈 #2~#6 완료: 패키지 구조, 기술통계 API, CSV 로더, SciPy 대조 테스트, CI
- 모든 PR이 자동 검증을 통과하도록 만들기
- 다음 주 기능 구현이 바로 시작될 수 있는 수준의 기반 확보

### Action

- Day 1에 `src/` 레이아웃과 `pyproject.toml`, 린트·타입·테스트 설정을 먼저 고정했다.
- 기술통계 API는 구현과 동시에 SciPy 대조 테스트를 작성하는 방식으로 진행했다.
- CI를 늦게 붙이지 않기 위해 #6을 첫 주 중반에 배치하고, Python 3.10~3.13 매트릭스를 구성했다.
- 매일 15분 동기화로 이슈별 막힘을 공유했다.

### Result

- 이슈 **5/5 완료**, 테스트 커버리지 **92%**, CI 그린.
- 기술통계 API의 `ddof`/`NaN` 정책을 초기에 문서화해 이후 검정·회귀에서 재작업이 없었다.
- 다만 개발 환경 구성이 계획(0.5일)보다 **1.5일** 걸렸고, Python 3.13의 타입 스텁 이슈로 CI가 반나절 지연되었다.
- CI를 첫날 바로 붙였다면 이 지연을 더 빨리 발견했을 것이다.

## Sprint 2 — 분석 기능 확장 (2026-11-16 ~ 11-20)

### Situation

Sprint 1에서 만든 기반 위에 확률분포·가설검정·상관·회귀를 올려야 했고, 동시에 0.1.0 릴리스가 걸려 있었다.
7개 이슈 중 #7(정규분포)과 #8(t-검정), #9(상관)와 #10(회귀)가 각각 의존 관계를 가지고 있었다.

### Task

- 이슈 #7~#13 완료: 정규분포, t-검정, 상관계수, 선형 회귀, 성능 최적화, 분산 정확도 fix, 문서
- 0.1.0 릴리스 후보를 금요일까지 완성
- 성능 개선과 수치 안정성을 수치로 증명

### Action

- 의존성 순서대로 분포 → 검정 → 상관/회귀를 배치하고, 각 단계마다 SciPy 대조 테스트를 통과시켰다.
- 수치 계산 코드는 혼자 리뷰하지 않고, 구현자와 리뷰어가 역할을 바꿔 교차 검토했다.
- #11은 벤치마크를 먼저 작성하고 before/after를 기록하는 방식으로 진행했다.
- #12는 재현 케이스를 테스트로 먼저 만들고 Welford 방식으로 교체했다.
- 금요일에 릴리스 버퍼를 두고, 목요일까지 기능 개발을 끝내는 것을 목표로 했다.

### Result

- 이슈 **7/7 완료**, **0.1.0 배포**.
- 100만 행 기술통계 처리 시간 **2.8초 → 1.0초 (약 64% 개선)**.
- SciPy 대조 테스트 덕분에 분산 계산의 부동소수점 오차를 릴리스 전에 발견했다.
- 아쉬운 점: 문서(#13)가 릴리스 당일로 몰렸고, #11과 #12가 후반에 겹치며 금요일 여유가 줄었다.
- "기능 완료"와 "릴리스 준비 완료"는 다르다는 것을 체감했다.

## 2주 전체 회고

### 잘한 점

- **수치 코드에 대조 테스트를 먼저 붙인 것.** 구현 속도는 조금 느려도, 릴리스 전에 오류를 잡는 비용이 훨씬 낮았다.
- **이슈를 1일 단위로 쪼갠 것.** 지연이 발생한 날 바로 다음 계획을 조정할 수 있었다.
- **성능 개선을 감이 아니라 벤치마크로 증명한 것.** 리뷰와 회고에서 같은 숫자를 공유할 수 있었다.

### 아쉬운 점

- 환경 설정과 CI를 첫날 한 번에 끝내지 못해 Sprint 1 초반이 예상보다 느려졌다.
- 문서를 후반에 몰아넣어 릴리스 당일 부담이 커졌다.
- 테스트가 "정상 입력" 중심이어서, 결측치의 **위치 조합**까지 검증하지는 못했다.

### 다음 사이클 원칙

1. **Why**: 통계 라이브러리의 신뢰는 기능 수가 아니라 결과의 정확성에서 나온다.
2. **What**: 새 기능은 "구현 + SciPy 대조 + 경계값 테스트 + 문서"를 한 묶음으로 완료한다.
3. **How**: 기능 동결일을 수요일로 고정하고, 목요일은 문서·릴리스, 금요일은 검증·회고에 쓴다.
